# Part 7 — ETL Process Design

> Implementations: [sql/etl/](../sql/etl/) (01_staging → 04_load_facts). Spark-side ETL: doc 07.

## Architecture

```
 SOURCES                 STAGING (stg)              WAREHOUSE (dim / fact)
 ┌───────────┐  Extract  ┌──────────────┐ Transform ┌───────────────────────┐
 │ TrafficOLTP├─────────►│ stg.Sensor…  ├──────────►│ 1. Load dimensions     │
 │ (watermark)│          │ truncate-and-│           │    (SCD 1/2/3 MERGE)   │
 └───────────┘           │ -load, typed │           │ 2. Load facts          │
 ┌───────────┐           │ NOT enforced │           │    (SK lookups,        │
 │ Spark gold ├─────────►│ stg.Hourly…  │           │     unknown member,    │
 │ Parquet    │  JDBC    └──────────────┘           │     late-arriving)     │
 └───────────┘                 │                    │ 3. Update accumulating │
                               ▼                    └───────────────────────┘
                        etl.BatchLog / etl.RowLog / etl.ErrorLog / etl.Reject*
```

**Dependency order (hard rule): dimensions before facts.** Facts perform SK lookups against
current dimension rows; loading facts first would orphan them.

## Extract

- **OLTP reference data** — *incremental by high watermark*: every mutable OLTP table has
  `ModifiedAt datetime2`. (There is **no** `rowversion` column — see the limitation noted
  in doc 02.) `etl.WatermarkControl` stores the last extracted
  value per table; each run captures one upper bound and extracts
  `WHERE ModifiedAt > @lastWatermark AND ModifiedAt <= @watermarkUpper`. The extract proc
  **returns** the upper bound instead of persisting it; `etl.usp_AdvanceWatermarks` writes it
  as the **final step of `usp_RunNightlyPipeline`** — so a failure anywhere in the pipeline
  (dimensions, facts) leaves the watermarks untouched and the rerun re-extracts the same
  delta (restart-safe).
- **File feeds (CSV/JSON)** — landed to the lake and processed by Spark (doc 07); Spark's
  gold output is bulk-inserted into `stg.*` via JDBC.
- **Full load** — supported for initial population and disaster recovery:
  `EXEC etl.usp_RunNightlyPipeline @LoadDate = '<date>', @FullLoad = 1` resets every
  watermark to `1900-01-01` so the next extract reads the whole source;
  SCD2 logic is naturally idempotent (unchanged hashes → no-op), so a full re-extract does
  not create duplicate versions.

## Transform (rules implemented in staging→dim/fact procs and Spark)

| Rule class | Examples |
|---|---|
| **Data cleansing** | Trim/upper-case codes; normalize `'N/A'/''/'-'` to NULL; standardize direction codes (`NB/SB/EB/WB`). Out-of-range occupancy is **quarantined, not clamped** — silently rewriting a measure would hide a broken sensor |
| **Validation** | Speed in (0, 250] km/h; timestamps not in future & within batch window; FK candidate exists or → unknown/inferred member; mandatory columns present |
| **Duplicate removal** | Dedup on the business event identity `EventID` — `ROW_NUMBER() OVER (PARTITION BY EventID ORDER BY …) = 1`. Spark orders by `event_ts DESC, _source_file, detector_code` (**not** `_ingest_ts`: that is `current_timestamp()`, one constant per query, which made the survivor arbitrary); the SQL load orders by `EventTimestamp DESC`. Duplicates are quarantined with reason `DUPLICATE`, never dropped |
| **Derivation** | `SpeedOverLimitKmh`, `CongestionIndex = 1 − AvgSpeed/SpeedLimit`, weather banding, DateKey/TimeKey computation |

Rejected rows are **never discarded**: they go to `stg.RejectTrafficEvent` with
`RejectReason` and `BatchID`, are counted in `etl.RowLog`, and can be replayed after fixes.

## Load

### Dimension loading
- SCD1: `MERGE` update-in-place.
- SCD2: `MERGE` with hash-diff change detection; expired + new version rows in one statement
  (the INSERT of new versions is driven by `OUTPUT $action` into a table variable — the
  standard pattern to work around MERGE's single-insert limitation).
- SCD3: targeted `UPDATE` shifting Current→Previous columns.
- Each dimension seeds its **Unknown member (SK −1)** idempotently.

### Fact loading
- **FactTrafficEvent** (transaction): insert-only, batch-scoped delete-then-insert per
  `(BatchID)` for reprocessing safety; SK lookups join staging BKs to *current* dimension
  rows — except **point-in-time correctness for SCD2**: events join DimRoadSegment/DimSensor
  on BK **and** `EventDate BETWEEN EffectiveDate AND ExpirationDate`, so historical events
  attach to the version valid at event time.
- **FactHourlyTraffic** (periodic): idempotent **delete-and-reload per load date** (an upsert
  keyed on the SCD2 surrogate would leave rows of older segment versions behind when a date
  is reprocessed after a version change); zero-traffic rows generated by cross-joining the
  segment dimension with the hour spine.
- **FactIncidentLifecycle** (accumulating): `MERGE` — new incidents inserted with Unknown
  (−1) milestone keys; existing rows have milestone keys/lags **updated** as timestamps arrive.

### Late-arriving dimensions (inferred members)
A sensor feed can mention `SerialNumber = 'SNS-9999'` before asset management registers it.
Policy: the fact load **creates an inferred member** — a skeleton DimSensor row
(`IsInferred = 1`, attributes 'Unknown', real BK) — and uses its SK. When the real attributes
later arrive, the SCD process updates that same row **as Type 1** (overwrites the skeleton,
first real version) and clears `IsInferred`. Facts never wait, never drop, never mis-key.

### Unknown member (−1)
Used when the BK itself is missing/null (nothing to infer). Guarantees inner joins never
lose fact rows and reports show an explicit "Unknown" bucket instead of silently shrinking totals.

## Error Handling & Logging

- `etl.BatchLog` — one row per pipeline run: status Running/Succeeded/Failed, timings.
- `etl.RowLog` — per step: extracted / inserted / updated / rejected row counts (reconciliation:
  extracted = loaded + rejected must hold, checked by `etl.usp_ValidateBatch`).
- `etl.ErrorLog` — TRY/CATCH in every proc captures `ERROR_MESSAGE/LINE/PROCEDURE`, marks
  the batch failed, and re-throws; a failed batch leaves watermarks untouched → safe rerun.
- All procs are **idempotent per batch** — rerunning a failed batch cannot double-load
  (delete-by-date reloads for the transaction and snapshot facts, keyed MERGE for the
  accumulating fact and dimensions).

## Scheduling

Nightly full pipeline (OLTP extract → dims → facts) + hourly `FactHourlyTraffic` refresh.
Orchestrated by SQL Agent in the base project; the Airflow DAG in
[orchestration/](../orchestration/) shows the production-grade alternative with
dependencies, retries and SLAs (bonus, doc 11).
